# Synthetic evaluation and remaining work

Measurements are generated by `backend/evaluate.py`; the complete per-file evidence and raw
counts are in [`samples/evaluation.json`](../samples/evaluation.json). The website imports a
generated JSON summary from the same run, so results are not manually transcribed.

## Dataset and results

56 distinct synthetic documents, 20 forensic fixtures (8 clean, 12 tampered), 6 detailed scenarios,
and 6 additional applications containing 3 institution-specific supporting documents each.
Issuing authorities are simulated. Fixed scrutiny date: 26 October 2026.

| Criterion | Observed result | Qualification |
|---|---|---|
| Field extraction | 225/227 = 99.1% | Scalar text fields; production normalisation/fuzzy matching, not strict character equality. Missing fields count as errors. Infrastructure GPS/counts and structured roster lists are excluded. |
| Classification | 56/56 | Classifier prediction, independent of upload declaration. |
| Validation | 32/39 = 82.1% expectation coverage | Kind/target matching, exact verification states where supplied. Free-text labels are incomplete and some describe multiple findings, so this is a coverage proxy, not precision, recall or F1. |
| Anomaly detection | Precision 100%; recall 41.7%; clean false-positive rate 0% | TP 5, FP 0, FN 7, TN 8. Flags at MINOR or above count as detections. Small fixture set; zero observed FP does not imply zero real-world FP. |
| Source verification | 32/42 = 76.2% conclusive; 42/42 expected states | Conclusive means VERIFIED, MISMATCH_DETECTED or EXPIRED. Pending/unavailable/manual results stay in the denominator. NOT_APPLICABLE is excluded. |
| Source discrepancy | Precision/recall 100% on 5 planted mismatches | TP 5, FP 0, FN 0; small simulated sample. Record-mismatch precision still needs independent labels. |
| Processing time | Original ingestion mean 6.985 s/file; p95 25.646 s | 56 distinct files. Recorded ingestion timings precede the derived-analysis refresh; they are a baseline, not a fresh end-to-end run of the final extractors. Fresh validation mean/p95 are generated per run. |
| Alert timeliness | Created in the validation transaction | Verified by implementation and API tests. End-to-end delivery latency has not been measured. |
| Manual effort | Estimated manual baseline 2.07 h/application | Assumes 12 min/document + 45 min/application across 79 uploads and 12 applications. No user time study; not a measured time saving. |

Six canonical verification states: VERIFIED 25; MISMATCH_DETECTED 5; EXPIRED 2;
VERIFICATION_PENDING 2; SOURCE_UNAVAILABLE 1; MANUAL_REVIEW_REQUIRED 7.

The intentionally misdeclared occupancy certificate remains a mismatch in its application.
For the file-level benchmark, extraction/verification use the classifier's predicted type, not
the wrong upload label and not the ground-truth label. Thus a deliberate declaration error is
not miscounted as an authentication false positive. OCR and decoded QR evidence are retained
from ingestion; this evaluation refreshes extraction and source verification, not those stages.

The generator and implementation share a team and document templates. These are development
fixtures, not a held-out test set. Thresholds are illustrative and have not been calibrated on
real AICTE applications. Do not present these numbers as production accuracy.

## Reproduce

Use a dedicated local demo database, never a production database. For a fresh run:

```bash
cd backend
uv sync
uv run python -m seed.seed
uv run python -m seed.seed --refresh
uv run python evaluate.py
uv run pytest
```

`--refresh` updates synthetic institutional records and recomputes extraction, forensics and
verification from retained uploads/OCR/QR. It preserves workflow states and reviewer-modified
findings. `evaluate.py` revalidates without advancing workflow and appends audit/validation records.
Do not run it on an officer-modified database when comparing benchmark numbers: findings reflect reviews.
Source comparisons use in-process mock authorities, with the dataset's deliberate 202/503 cases.
The report includes the manifest hash, source-file hashes, base Git revision and working-tree note.

Start backend and frontend as in the README. With Microsoft Edge installed:

```bash
cd frontend
npm ci
npm run typecheck
npm test
npm run build
# Set VERISENSE_URL to the running frontend, e.g. http://localhost:5176
node scripts/smoke-ui.mjs
```

The browser script assumes a freshly seeded demo's application IDs. It logs in through the UI,
opens public pages, checks mobile overflow, visits every application/tab, switches the ELA overlay,
and captures screenshots in `docs/images/`. It does not record recommendations or final decisions.

## What still needs to be done

1. Improve tamper detection, especially pasted-value scans and same-font rewrites (7/12 missed).
   Expand and independently label a held-out set before changing detection thresholds.
2. Label every rule/finding and negative case to measure validation precision, recall and F1,
   plus record-discrepancy precision. The current free-text expectation list is insufficient.
3. Run a fresh final-version ingestion benchmark, measure submission-to-alert delivery latency,
   and conduct an officer time study with a measured manual baseline.
4. Validate real scans across languages, issuers and poor capture conditions; calibrate risk bands
   using adjudicated outcomes. The two remaining scalar extraction errors are available in raw JSON.
5. Replace simulated authorities with authorised integrations; configure production secrets,
   storage/database, retention, deployment monitoring and an accessibility review.
6. Review dependency vulnerabilities reported by `npm ci`; update and regression-test the affected
   packages before deployment. The browser walkthrough is a smoke check, not an accessibility or security audit.
